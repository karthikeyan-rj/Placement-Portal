# Phase 7P.5 — Rich Staff Profiles (PC / PO)

**Status:** Complete and verified. No commit created; `HEAD` remains `3344754`.

Adds a dedicated, editable professional profile for `PC` and `PO`, backed by a new
`staff_profiles` table. `STUDENT` and `PR` behaviour is unchanged and continues to use
`StudentProfile`.

---

## 1. Scope and decisions

| Item | Decision |
|---|---|
| Roles with a staff profile | `PC`, `PO` |
| Roles unchanged | `STUDENT`, `PR` (still `StudentProfile`) |
| Editable fields | phone, designation, office location, bio, LinkedIn URL, expertise |
| Read-only (owned by `User`) | full name, email, role, account status, department |
| Avatar | Initials only — no upload feature |
| Expertise storage | Single `jsonb` column, `List<String>` |
| Row creation | Lazy, on first successful save. `GET` never creates |
| Ownership | Derived only from the JWT; no user ID in path, body, or query |
| Migrations | None in the project. Local `ddl-auto: update`; production is `validate` (see §8) |

### Field validation

| Field | Rule |
|---|---|
| `phone` | blank, or 6–25 characters from digits, spaces and `+ - ( ) .` |
| `designation` | max 120 |
| `officeLocation` | max 150 |
| `bio` | max 1000 |
| `linkedinUrl` | max 500, absolute `http`/`https` URL with a host |
| `expertise` | max 12 entries, each non-blank, max 60 characters |

Update semantics:

* Omitted **or** `null` → field left unchanged.
* `""` (blank string) → field cleared to `null`.
* `expertise: []` → expertise cleared.
* A list containing a blank entry → `400`.
* Values are trimmed; expertise is de-duplicated case-insensitively, preserving first-seen order.

## 3. API

### `GET /api/profile/me`

Response extended with `staffProfile`; field is always present for `PC`/`PO` (all-null when
no row exists) and `null` for `STUDENT`/`PR`.

```json
{
  "data": {
    "role": "PC",
    "studentProfile": null,
    "staffProfile": {
      "phone": "+91 98765 43210",
      "designation": "Placement Coordinator",
      "officeLocation": "Block C, Room 214",
      "bio": "I coordinate campus placements ...",
      "linkedinUrl": null,
      "expertise": ["Campus Recruitment", "Java", "SQL"]
    }
  }
}
```

`StaffProfileResponse` exposes only these six fields — no `id`, `userId`, or timestamps.

### `PUT /api/profile/me/staff`

Partial update of the caller's own profile. No user identifier is accepted.

| Caller | Result |
|---|---|
| `PC` / `PO` | `200` with the saved `staffProfile` |
| `STUDENT` / `PR` | `403` |
| anonymous | `401` |
| invalid field | `400` |

## 8. Production deployment note

The project has no migration tool, and production runs with `ddl-auto: validate`, so the
table must exist before the new code starts. Apply once:

```sql
CREATE TABLE staff_profiles (
    id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id         BIGINT NOT NULL UNIQUE REFERENCES users(id),
    phone           VARCHAR(25),
    designation     VARCHAR(120),
    office_location VARCHAR(150),
    bio             VARCHAR(1000),
    linkedin_url    VARCHAR(500),
    expertise       JSONB,
    created_at      TIMESTAMP(6),
    updated_at      TIMESTAMP(6)
);
```

`staff_profiles` is additive and holds no existing data, so this does not touch any
current table.

## 9. Defects found and fixed during verification

1. **Clearing LinkedIn returned 500.** `linkedinUrl: ""` reached `URI.create("")`, which
   throws. Normalisation now runs only for non-blank values, so a blank string clears the
   field as intended.
2. **Dangling `aria-controls`.** Inactive tab panels were unmounted, so each inactive tab's
   `aria-controls` pointed at a non-existent element. All panels are now mounted with
   inactive ones `hidden`.
3. **Test isolation defect.** Two new tests asserted the whole `staff_profiles` table was
   empty, which failed once live verification had legitimately created two rows. They are
   now scoped to the fixture users (`findByUserId(...).isEmpty()`), so the suite no longer
   depends on pre-existing local data.
4. **Unrelated compile fix.** Removed a UTF-8 BOM from
   `backend/src/test/java/com/college/placement/contact/ContactRequestGrantApiTest.java`
   (a pre-existing untracked file) that prevented test compilation. No logic changed.
